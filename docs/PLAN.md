# SpinYarn 扩展计划

> 状态：5 节均已实现（2026-08）。

## 1. 运行时自动下载缺失版本映射（最高优先）

**背景**：当前版本支持 = 嵌入式表（43 版本）∪ 外部映射目录。新版本（如未来的 `1.21.12` 正式版、`1.18.2-pre1` 预发布）不在本地 → 透传，无法反混淆。参考 Sherlock `FabricMavenMapLocator`（解析 `maven-metadata.xml` 取最大 build）。

**Mojang 版本号新规则（2026 起，须纳入版本识别）**：
- **正式版新格式 `YY.D.H`**：两位数年份 `.` 当年 drop 序号 `.` hotfix 计数（首 drop 无 hotfix）。最后一个 `1.` 前缀版本为 `1.21.11`，例：`26.1`、`26.2`、`26.1.1`
- **快照新命名 `YY.D Snapshot N`**：自 `26.1 Snapshot 1`（2025-12）起替代旧 `YYwNNn`（如 `18w10d`），例：`26.1 Snapshot 1`、`26.3-snap-6`
- **关键：Minecraft 26.1+ 已移除混淆**（Sherlock 已验证；Fabric Maven 无任何 26.x 映射，最新仍 `1.21.11+build.6`）→ 26.x 系日志本身可读，**无需映射、无需下载，直接透传即正确**

**范围**：
- 请求版本不在本地（`is_version_supported=false`）且属于需要映射的 `1.x` 系时，自动从 Fabric Maven 下载
- 覆盖正式版（`1.21.12`）、预发布（`1.18.2-pre1`）、候选（`1.21.11-rc2`）
- **排除**：Minecraft 周快照（`25w44a`）、一切非标准版本、**26.x 新格式版本**（`YY.D.H` / `YY.D Snapshot N`，无混淆，透传即可）

**设计**：
- 版本识别 `is_downloadable_version(v)`：正则 `^1\.\d{1,2}(\.\d{1,2})?(-(pre|rc)\d+)?$`——仅 `1.x` 系触发下载（有混淆、有 yarn 映射）；周快照 `25wxx`、新格式 `26.x`（`YY.D.H`/`YY.D Snapshot N`）天然不匹配，直接透传
- 定位 build：请求 `maven.fabricmc.net/net/fabricmc/yarn/maven-metadata.xml`，正则抽取 `<version>`，匹配 `^<请求版本>((?:\+build)?)\.(\d+)$` 取最大 build
- 下载：URL `…/yarn-<mvn版本>-tiny.gz` → 写入 `<mappings_dir>/<version>.tiny.gz`（原始名，不带 `+build`）
- 触发点：`process` 中 `is_version_supported=false` 且可下载 → `spawn_blocking` 下载 → 成功则继续正常加载反混淆
- **失败降级**：定位不到 / 下载失败 / 网络不可达 → 保持透传（`success:true`，计数 0），不报错
- **幂等并发**：下载前复查文件存在；临时文件 + `rename` 原子落盘；多请求并发下载同一版本安全
- **缓存 TTL（7 天）**：落盘文件以文件 mtime 记录下载时间，TTL 7 天。请求时若文件存在但已过期（mtime 距今 ≥ 7 天），触发重新下载（获取更新的 yarn build）；**过期后重下载失败则回退使用旧文件**，不因网络抖动丢可用性。正式版/用户手动放置的映射同样受 TTL 约束（重下载无害）
- **成本**：映射文件本身很小（metadata ~140KB + 映射 ~0.8-1.2MB），传输量极小；200mbps 带宽下理论传输 <100ms，实际主要受服务器到 Fabric Maven 的网络往返影响。实测 Termux 链路约 1.5-1.8s，服务器链路待验证，通常应 <1s。**下载一次即落盘缓存 7 天，期间后续请求零开销，仅 7 天到期后首次请求重下载一次**
- **安全**：版本字符串白名单正则校验后才拼接 URL，防路径注入；仅允许 `maven.fabricmc.net`
- 可选配置开关 `maven.auto_download`（默认开启），内网部署可关闭

**依赖**：引入 `ureq`（轻量同步 HTTP，放 `spawn_blocking`；不重新引入重量的 `reqwest`）；maven-metadata 用正则抽取 `<version>`，不引 XML 库

**测试**：
- 单测：`is_downloadable_version` 边界（正式/pre/rc/周快照/日期/非法/26.x 新格式）
- 端到端：`1.18.2-pre1` 真实样本自动下载并反混淆（复用 Sherlock 样本）
- 26.x 透传：请求 `26.2`/`26.1 Snapshot 1` → 不触发下载，直接透传（无混淆，输出即正确）
- 失败路径：网络不可达 → 透传

**风险**：运行时引入网络依赖（内网部署靠开关关闭）；首次请求该版本需一次 metadata + 映射下载，落盘缓存 7 天，到期后重下载失败会回退旧文件

## 4. LRU 热门版本缓存（实验性）

**动机**：长尾流量下每请求固定加载成本 ~110ms。引入有界 LRU 缓存抵消热版本加载成本；水位线淘汰动态控制内存。实验目的：验证 LRU 在真实 LogShare 流量下是否被"烫成全量"（频繁驱逐、无热点）还是热点集中驻留。

**设计**：
- 结构：`Mutex<HashMap<String, (Arc<Mappings>, u64)>>`，上限 32 条目（高水位 30 触发淘汰至低水位 20）
- 命中：`Arc` 共享解析后表（只读），跳过加载；未命中：加载 → 插入 → 触发水位线检查
- **水位线淘汰**：插入后 `len ≥ 30`（高水位）→ 批量淘汰最久未用到 `20`（低水位），缓存大小在 20~30 间波动，避免长期满载
- **LineEngine 重构**：改为持有 `Arc<Mappings>`（当前 `new(Mappings)` 按值 move，缓存命中需共享，避免深拷贝 ~10MB）
- 与 7 天磁盘缓存（gzip 文件）两层独立：内存 LRU 存解析后表
- 与 `GATE`：命中请求不加载映射，暂保留 permit 语义（简化）
- 可观测性：命中率 / 驱逐次数 / 当前条目数暴露于 `/health` 或日志，用于评估是否"被烫成全量"

**配置**：config.toml 新增 `[cache]` 段：`enabled`（默认 true）/`max_entries`（32）/`high_watermark`（30）/`low_watermark`（20）

**测试/评估**：
- 单测：命中/未命中/驱逐到水位线/并发安全
- 真实流量观察：命中率与驱逐频率，判断热点是否集中
- 内存实测（Termux arm64）：单版本解析表 ~10MB；缓存 20 条目 ~189MB、峰值 30 条目 ~300MB（服务器可承受）

**风险**：常驻内存 20~30 条目约 189~300MB；引擎 Arc 重构（已完成）；缓存击穿（并发 miss 同版本重复加载，后续可加 loading 合并）

**后续（依据实验结论）**：
- 命中率高、驱逐少 → 扩大条目数或上全量缓存
- 被"烫成全量"（频繁驱逐）→ 回退无缓存，维持现状

## 5. 部署模型调整：映射外置 + 同级配置文件

**背景**：当前映射表编译期嵌入二进制（`build.rs` + `include_bytes!`），单文件部署（二进制 ~41MB，其中 ~31MB 为映射数据）；配置文件从当前工作目录 / `/etc/spinyarn` 查找。

**目标**：
- 映射表**不再内置二进制**，改为运行时从与二进制同级的 `./mappings/` 目录加载
- 配置文件（`config.toml`）同样放在与二进制同级目录
- 收益：新增/更新版本无需重新编译（与第 1 节自动下载天然契合）；二进制缩小至 ~9MB（去掉映射数据）

**设计**：
- 删除 `build.rs` 嵌入逻辑与 `embedded.rs`（或保留为编译期可选，默认关闭）；`load_mappings` 只从外部目录加载
- 目录定位：基于可执行文件路径（`std::env::current_exe()` 的父目录）下的 `./mappings`，而非依赖进程当前工作目录
- 配置查找：优先二进制同级 `config.toml`，再回退当前工作目录 / `/etc/spinyarn/config.toml`
- 默认 `maven.mappings_dir` 指向二进制同级的 `./mappings`，与第 1 节自动下载落盘、第 4 节 LRU 加载的目录统一
- 端口自动递增、其余配置项不变

**影响**：
- **单文件部署特性失效** → 部署需携带 `二进制 + mappings/ 目录`（配置可选）
- 新增版本 = 拷贝或自动下载映射文件即可，无需重编译
- 二进制体积 ~9MB

**测试**：
- 二进制在不同工作目录启动时，仍能正确找到同级 `mappings/` 与 `config.toml`
- 移除嵌入逻辑后 43 版本外部目录加载回归（复用现有 fixtures）
- 自动下载（第 1 节）落盘到同级 `mappings/`

**风险**：目录定位依赖 `current_exe`（符号链接场景需 resolve）；部署形态变化需同步更新 AGENTS.md「单文件部署」记录与 CI/release 打包流程
